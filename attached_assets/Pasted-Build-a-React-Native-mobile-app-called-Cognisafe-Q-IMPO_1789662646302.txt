Build a React Native mobile app called "Cognisafe-Q".

IMPORTANT:
This is a 3-day hackathon MVP. Prioritize a working, polished demo over production-grade architecture.

The app demonstrates a smartphone-based vehicular safety system that:

1. Reads accelerometer and gyroscope data.
2. Buffers sensor readings into 150 × 6 windows.
3. Sends windows to an inference layer.
4. Receives SAFE, ALERT or EMERGENCY status.
5. Shows an ALERT confirmation countdown.
6. If the driver does not respond, triggers an emergency flow.
7. Gets the driver's GPS location.
8. Displays that an emergency alert has been sent.
9. Allows the driver to manually trigger SOS.

The research architecture uses accelerometer + gyroscope data, 150 × 6 temporal windows with stride 15, abnormal-motion detection, behavioral refinement, temporal consistency, user confirmation and emergency escalation.

==================================================
SENSOR SYNCHRONIZATION
==================================================

Accelerometer and gyroscope are separate event streams.

Do NOT simply assume every accelerometer event corresponds
perfectly to the same gyroscope event.

Maintain the latest accelerometer and gyroscope readings.

Use timestamps to combine sufficiently close readings.

For the MVP, a small synchronization tolerance is acceptable.

Once a synchronized sample is created:

push:

[
  ax,
  ay,
  az,
  gx,
  gy,
  gz
]

into the sensor buffer.

==================================================
BUFFERING
==================================================

Constants:

WINDOW_SIZE = 150

STRIDE = 15

Maintain an in-memory buffer.

When:

buffer.length >= 150

create:

150 × 6

window.

Example:

[
  [ax, ay, az, gx, gy, gz],
  [ax, ay, az, gx, gy, gz],
  ...
]

Send this window to:

predictSensorWindow()

After the window is processed:

remove the first 15 samples.

Therefore:

Window 1:
samples 1–150

Window 2:
samples 16–165

Window 3:
samples 31–180

Continue while monitoring is active.

Do NOT send individual sensor readings to the backend.

==================================================
SAMPLING
==================================================

Target approximately 50 Hz.

Use the highest stable sensor update rate supported by the device.

Do not assume that every phone will provide exactly 50 readings
per second.

The app must remain stable if the actual sensor frequency varies.

The important requirement is:

150 samples per inference window
with stride 15.
